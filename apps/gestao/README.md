# GOGDELY Gestão
Protótipo Flutter local para Windows com dashboard, pedidos, KDS, PDV, estoque, relatórios, financeiro e configurações. Com `GOGDELY_LOCAL_API=true`, dashboard, pedidos e KDS consultam automaticamente a API local a cada 3 segundos. O painel reúne pedidos fictícios das dez lojas e oferece um filtro por estabelecimento; os botões salvam preparo, pronto e encaminhamento ao Entregador. O Cardápio permite escolher a loja, editar produtos, preços, fotos, disponibilidade e adicionais. Ficha técnica, movimentações de estoque, mesas QR e PDV continuam no piloto Burger House. Relatórios e financeiro permanecem ilustrativos; a seleção local de loja não equivale a autorização multiempresa.

O projeto agora compila também para Web (`flutter build web --release`) como **prévia PWA da Gestão**. O build padrão não ativa a API local; sem autenticação e isolamento por empresa, essa prévia não deve ser publicada como painel operacional. A publicação online depende da API gerenciada, perfis reais, autorização por filial e revisão das mídias/licenças.

No **KDS**, o menu de ações de um pedido novo ou em preparo permite **Marcar prioritário** e **Voltar à ordem normal**, sempre com motivo. Os prioritários aparecem primeiro; em cada grupo vale a ordem de chegada. A prioridade e seu histórico ficam apenas no SQLite de teste, sem permissões por operador ou setor.

Em **Pedidos**, o menu de ações permite **Registrar pagamento simulado** para pedidos não cancelados com forma de pagamento escolhida, sempre com motivo. O cartão passa a mostrar `pagamento simulado no laboratório (sem cobrança real)` e a declaração fica no histórico do pedido. É apenas registro de teste: nada é cobrado, transferido ou confirmado financeiramente, e nenhum provedor é acionado.

O mesmo menu oferece **Imprimir comanda**, que abre no navegador uma comanda 80mm do pedido (itens, mesa/canal, prioridade e total) pronta para impressão local — sem valor fiscal e sem integração com impressora térmica real (GOG-031 em simulação).

Em **Configurações**, o seletor **Papel local** (Gerente, Caixa, Cozinha) simula permissões (GOG-037): só o Gerente cancela pedidos, Caixa e Gerente registram pagamentos simulados, Cozinha e Gerente mudam prioridade. A troca é livre e não representa autenticação ou controle de acesso real.

No VS Code, abra a raiz `C:\Projetos\GOGDELY`, selecione `GOGDELY Loja / Restaurante • Gestão (Windows)` em Executar e Depurar e pressione F5. Também é possível abrir somente `apps/gestao`; o arquivo `.vscode/launch.json` dessa pasta oferece o mesmo F5. Para abrir os três apps rapidamente com a API local, use `GOGDELY • Cliente + Gestão + Entregador (F5)` na raiz.

# Cardápio local das lojas fictícias

Com o perfil F5 de banco local, abra **Cardápio** na Gestão e escolha um estabelecimento fictício para cadastrar ou editar produtos. Nome, descrição, categoria, preço, promoção, disponibilidade, foto e adicionais são salvos por loja. Use **Escolher foto do computador** para PNG/JPEG/WebP de até 5 MB; fotos ficam em `services/api/.local/uploads`, fora do Git. Os adicionais são informados um por linha no formato `Bacon; 4,00`. A ficha técnica e o ajuste de saldos detalhado continuam exclusivos da Burger House: cadastre ingredientes em **Estoque** e depois vincule cada um no Cardápio, uma linha por ingrediente como `carne; 180`. O Cliente consulta o mesmo catálogo e a API calcula os preços dos pedidos. Permissões por funcionário, autorização por empresa e teste visual do proprietário ainda estão pendentes.

Em **Mesas QR**, copie a ficha de uma mesa M01–M10 e cole o link no navegador do próprio computador para imprimir o QR. O cardápio HTML aceita pedidos sem instalar app; a Gestão mostra mesa e horário e pode marcar o pedido como servido. Para abrir no **celular da mesma rede**, use o perfil F5 **GOGDELY API • Banco local na rede (LAN)** e acesse `http://<ip-do-computador>:8765/m/burger-house/M01`; QRs impressos a partir do IP da rede funcionam no celular (veja [services/api/README.md](../../services/api/README.md)). Nunca exponha essa API à internet.

Em **PDV**, escolha produtos disponíveis, quantidades e uma forma de pagamento pretendida; **Salvar pedido de balcão** grava o pedido na API/SQLite local, baixa o estoque e o coloca em **Pedidos/KDS**. Depois do preparo, a Gestão pode marcar **Entregar no balcão**. A forma escolhida não confirma nem recebe pagamento. O painel **Caixa local** permite declarar abertura, suprimento, sangria e fechamento com motivo, consultar o histórico recente e comparar o dinheiro contado com o saldo esperado. Esses registros manuais não representam recebimentos confirmados nem conciliação financeira; ainda faltam permissões e validação visual do proprietário.
